合作方系統將「問答型知識點」（含附件）推送到 open333CRM 知識庫（KB）的單一端點。

動作（建立 / 更新 / 移除）由必填欄位 cmd 顯式指定，採整批覆蓋與軟刪語意。 詳細決策見 openspec design.md。

認證

所有請求必須帶 Authorization: Bearer pk_xxx，API Key 由 open333CRM 維運方私下提供，請勿提交進 git 或其他公開頻道。

設計原則

  • 顯式語意：動作由 cmd 明確指定，不靠 Ver 隱式推導
  • 整批覆蓋：UPDATE 與復活時附件「先刪後寫」
  • 冪等（idempotent）：DELETE 重複呼叫不報錯；UPDATE 收到舊版本不會倒退
  • 軟刪：DELETE 後 status=ARCHIVED，可由 CREATE 復活

knowledge

知識庫資料管理

推送單筆知識點（CREATE / UPDATE / DELETE）

合作方系統將一筆問答推送到 open333CRM 知識庫。動作由必填欄位 cmd 指定：

cmd 用途
CREATE 新增；既有 PUBLISHED → 409；既有 ARCHIVED → 復活
UPDATE 整批覆蓋內容 + 附件；不存在或 ARCHIVED → 404
DELETE 軟刪（status=ARCHIVED + 清向量）；附件保留；冪等

Ver 仍需嚴格遞增（CREATE/UPDATE 收到舊版 → 200 skipped），避免亂序重送把新版蓋成舊版。

動作（大小寫不拘，後端會 trim + 大寫化）

DocID
required
string <= 64 characters

合作方系統的文件編號，同一合作方下需唯一

Ver
integer >= 1

文件版本，必須嚴格遞增。CREATE/UPDATE 收到 Ver ≤ 既有版本 → skipped。 DELETE 不檢查 Ver。

VerCreatTime
string^/Date\(\d+\)/$

版本建立時間，毫秒 epoch（.NET-style）。CREATE/UPDATE 必填

AI_Q
string

AI 客服問題（對客戶端的問題文字）。CREATE/UPDATE 必填

AI_A
string

AI 客服回覆。CREATE/UPDATE 必填

Source
string

文件分類來源。CREATE/UPDATE 必填。 歷史相容：後端同時接受 Source 與 Soruce（拼字錯誤），新對接請用正確拼字 Source。

Spec
string

商品規格 / 活動說明的結構化資料；JSON 字串（合法 JSON）

IsAttached
boolean

是否含附件。CREATE/UPDATE 必填

Attached
Array of strings <binary> [ items <binary > ]

附件檔案。同一請求可重複出現多個 Attached 欄位（multipart form 同名 part 可多個）。 DELETE 時送上來會被後端忽略。
