# 功能區文件

本目錄以**產品功能區**為單位說明現況：使用者在後台看到的一個功能，由哪些模組、背景工作與前端頁面一起完成，有哪些規則與已知問題。一份文件通常跨好幾個程式模組，例如收件匣同時涉及 `conversation`、`webhook`、`ai` 與 `socket`。

想從程式模組的角度查，例如「`conversation` 模組掛在哪個路由」，請看[模組文件](../modules/README.md)。設計階段的規劃文件在上一層 `docs/`（例如 `04_CASE_MANAGEMENT.md`），與本目錄衝突時以本目錄與原始碼為準。

## 本目錄的文件

| 文件 | 使用者 | 適合解答的問題 |
| --- | --- | --- |
| [租戶後台](./tenant/README.md) | 租戶的客服與管理員 | 側欄每一項由哪些模組負責？一則訊息進來後經過哪些模組？各功能區有哪些規則與已知問題？（目錄，每個功能區一份） |
| [平台後台](./platform/README.md) | 平台營運方 | 每個領域負責什麼？改一個方案會連帶影響什麼？（目錄，每個領域一份） |
| [服務水準協議](./SLA.md) | 租戶的管理員 | 系統監控哪幾種時限？逾時之後做什麼？SLA 的程式碼為什麼分散在不同地方？ |

## 新增文件時

- 以讀者要解答的問題分章，不以程式碼的檔案結構分章。
- 開頭標明資料來源與核對日期。內容以原始碼為準。
- 已知缺陷寫進[實作落差紀錄](../system/AUDIT.md)，文件內以編號引用，不重複細節。
- 屬於租戶後台或平台後台的功能區，放進對應的子目錄，並加進該目錄 README 的文件表。
