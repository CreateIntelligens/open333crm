## Why

自動化規則頁是給管理員用的，但目前的畫面要懂程式才看得懂：

- 規則列表的觸發事件顯示程式代碼（`message.received`、`conversation.created`），看不出規則在做什麼；名稱很長時表格被撐寬，只看得到「名稱」一欄。140 條規則沒有搜尋也沒有篩選。
- 編輯頁的「優先級」只是一個數字，沒說數字大的先還是後；「命中後停止」看不懂。
- 條件區是英文的工程介面：`AND`、`+ Rule`、`+ Group`，說明寫「建構器組合 AND/OR 群組條件」。
- 「測試／模擬執行」要手寫 JSON 格式的 Facts。
- 觸發事件選單裡有 6 種事件永遠不會觸發（AUDIT AUTO-05），選單上看不出來，管理員建了規則卻從不執行。

## What Changes

- **規則摘要**：列表與編輯頁用一句話描述規則，例如「當收到訊息時，如果開啟案件數等於 0，就建立工單「客戶諮詢」」。
- **列表**：觸發事件改顯示中文；名稱過長時截斷；加上名稱搜尋與啟用狀態篩選；「命中後停止」改成名稱旁的標示；拿掉「描述」欄（摘要取代）；拿掉「執行次數」欄（AUDIT AUTO-02：自 `9255245` 起停止更新，數字會誤導）。切換啟用失敗時顯示錯誤（原本只寫 console）。
- **編輯頁用語**：「優先級」改名「執行順序」並說明數字越大越先檢查；「命中後停止」改成「這條規則執行後，不再檢查其他規則」並說明；條件區全部中文（全部符合／任一符合、新增條件、新增條件群組）；觸發事件下方顯示說明。
- **標示不會觸發的事件**：契約的事件定義加上 `dispatched: false`，選單上顯示「（目前不會觸發）」，選了之後提示規則不會執行。
- **試跑改成表單**：依規則條件用到的欄位產生輸入框，結果用中文說明會不會觸發、會執行哪些動作。試跑的是已儲存的版本，畫面上說明。

## Capabilities

### Modified Capabilities

- `automation-engine`：新增規則頁的可讀性需求（規則摘要、列表、編輯頁用語、試跑表單）。

## Impact

- `packages/automation`（事件說明與 `dispatched`，需重新 build）、`apps/web` 自動化列表與編輯頁
- 不改 API 與資料；既有規則不受影響。
- 「執行順序」沿用 `priority` 數字，不改存法。
