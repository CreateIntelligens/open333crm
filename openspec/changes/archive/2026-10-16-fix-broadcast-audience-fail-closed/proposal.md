## Why

2026-10-15 重寫操作手冊時盤點行銷廣播，發現幾條路徑會把廣播發給「該渠道的全部聯絡人」，而使用者以為只發給一部分人：

| 編號 | 問題 |
| --- | --- |
| M03 | 選「依標籤篩選」或「手動選擇」時，畫面沒有挑標籤或挑人的欄位。後端拿到空名單就不加條件，等於群發給全渠道 |
| M04 | 選「受眾分群」卻沒選分群，或分群在排程期間被刪掉，後端找不到分群時也不加條件，同樣群發給全渠道 |
| M05 | 分群條件值留空時，前端把空條件濾掉，剩 0 條；後端把 0 條件的分群當成「全部聯絡人」 |
| M06 | 「立即發送」按下後按鈕不會停用；後端允許 `sending` 狀態再次發送，且「檢查狀態→改成 sending」不是原子操作，重按或與排程器同時執行會重複群發 |
| M09 | 建立廣播時前端用小寫 `line`／`fb` 比對渠道類型，API 回的是 `LINE`／`FB`，所以素材下拉不會依渠道過濾；後端也不檢查素材與渠道是否相符 |

## What Changes

- 建立廣播時，`targetType` 為 `segment`／`tags`／`contacts` 但沒有指定分群、標籤或聯絡人，回 400 並指出欄位。分群沒有任何有值的條件也回 400。
- 發送廣播時（手動與排程），受眾無法解析（分群不存在、分群沒有條件、名單為空）一律停止發送並標為失敗，回中文原因，絕不退化成全發。
- 分群建立與修改時，至少要有一條條件，且每條條件都要有值；計算分群人數時，沒有有效條件的分群算 0 人。
- 立即發送只允許從 `draft`、`scheduled`、`failed` 轉成 `sending`，以單一條件更新搶占；搶不到（例如正在發送中）回 409。前端按下後按鈕停用並顯示處理中。
- 建立廣播時素材的渠道必須與廣播渠道相符。前端素材下拉依 `LINE`／`FB` 正確過濾。
- 前端：「依標籤篩選」加上標籤多選；「手動選擇」沒有挑人的介面，先從選項中隱藏；分群條件值空白時不能建立。

## Capabilities

### New Capabilities

- `broadcast-audience`：廣播受眾的解析規則、分群的有效條件、立即發送不可重複。

### Modified Capabilities

（無）

## Impact

- API：`marketing/marketing.service.ts`（`createBroadcast`、`executeBroadcast`、`resolveAudience`）、`marketing/segment.service.ts`
- Web：`app/dashboard/marketing/page.tsx`、新增 `lib/marketing/broadcast-form.ts`
- 既有資料：已建立、但 `targetType` 為 `tags`／`contacts` 且名單為空的草稿或排程廣播，發送時會被擋下並標為失敗（以前會發給全渠道）。沒有有效條件的既有分群，人數會在下次計算時變成 0，用它的廣播會被擋。
