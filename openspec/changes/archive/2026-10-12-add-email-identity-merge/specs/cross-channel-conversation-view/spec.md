# Spec Delta

## Purpose

讓客服在收件匣與聯絡人頁看到同一位聯絡人在所有渠道的對話，歸戶後不必逐一切換渠道查詢，並遵守客服的渠道可見性。

## ADDED Requirements

### Requirement: 收件匣顯示聯絡人在其他渠道的對話
收件匣右側面板 SHALL 列出目前聯絡人在其他渠道、且客服看得到的對話，每段顯示渠道、最後訊息時間與最後一則訊息摘要。客服展開一段對話時，SHALL 顯示該對話的訊息內容，不必離開目前的對話。

#### Scenario: 歸戶後查看 FB 對話
- **WHEN** LINE 聯絡人已與 FB 聯絡人歸戶，客服在收件匣開啟 LINE 對話
- **THEN** 右側面板列出 FB 對話，展開後顯示 FB 對話的訊息

#### Scenario: 沒有其他渠道
- **WHEN** 聯絡人只有目前這一段對話
- **THEN** 面板不顯示其他渠道的對話區塊

### Requirement: 聯絡人頁顯示跨渠道對話紀錄
聯絡人詳情頁 SHALL 提供「對話紀錄」分頁，把這位聯絡人在客服看得到的所有渠道的訊息依時間排成一條，每則訊息標示渠道與方向（顧客或客服／AI）。訊息以分頁載入，最新的在最後；更早的訊息由客服按「載入更早的訊息」載入。

#### Scenario: 合併後的時間軸
- **WHEN** 聯絡人有 LINE 與 FB 兩段對話，客服開啟「對話紀錄」分頁
- **THEN** 兩個渠道的訊息依時間交錯排列，每則標示 LINE 或 Facebook

#### Scenario: 載入更早的訊息
- **WHEN** 訊息超過一頁，客服按「載入更早的訊息」
- **THEN** 系統載入更早的一頁，不重複已顯示的訊息

### Requirement: 跨渠道對話依渠道可見性過濾
跨渠道的對話清單與訊息 SHALL 只包含客服可見渠道的內容。有看不到的渠道時，系統 SHALL 只回傳看不到的對話數量，不回傳其渠道名稱、訊息或摘要。查詢 SHALL 限定在客服所屬租戶，聯絡人不屬於該租戶時回 404。

#### Scenario: 分店帳號
- **WHEN** 只能看 LINE 渠道的客服查看一位同時有 LINE 與 FB 對話的聯絡人
- **THEN** 只顯示 LINE 的訊息，並顯示「另有 1 段其他渠道的對話」，不顯示 FB 的任何內容

#### Scenario: 其他租戶的聯絡人
- **WHEN** 客服以其他租戶的聯絡人 id 查詢跨渠道訊息
- **THEN** 系統回 404

#### Scenario: 缺少權限
- **WHEN** 角色沒有 `contact.view` 或 `inbox.view` 的客服查詢跨渠道訊息
- **THEN** 系統回 403
