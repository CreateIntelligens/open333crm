## Why

範本填空（階段 1）+ AI 生成（階段 2）已涵蓋約 90% 的 Flex 需求。剩下的少數進階場景——要自訂結構（增減區塊、調整巢狀、做範本沒有的版面）——需要「視覺結構編輯」。這對應原本規劃的三欄編輯器，但**記取 aitago 教訓後降為「進階選配」**：aitago 把這種編輯器當預設導致「太複雜」被使用者棄用。本階段明確定位為「少數進階使用者、從填空模式『轉為進階』才進入」，且**優先度最低——應先驗證真有需求再做**（aitago 的簡易模式已證明多數人不需要）。

## What Changes

- **進階視覺編輯模式**：從填空編輯器的「轉為進階編輯」進入。三欄：左結構樹（加/刪/拖曳排序元件）、中即時預覽、右屬性面板（含進階旋鈕，摺疊收納）。
- **結構樹 + 拖拉**：以樹狀忠實對應 Flex box 巢狀；引入拖拉套件做排序（避開 aitago 的「上移/下移按鈕」硬傷）。
- **視覺 ↔ 原始 JSON 雙向**：可切到 JSON 檢視/微調，改完回視覺。
- **借鑑 aitago 的好手法、避開壞的**：狀態用單一 LINE JSON、元件 allows 白名單宣告巢狀、屬性 config-driven、LINE 錯誤回貼欄位、undo/redo 快照；但**不維護三份平行表示、不重寫渲染引擎、不把全規格攤開**。

不在本階段範圍：carousel 多卡編輯（可再議）；本階段只在確認需求後才實作。

## Capabilities

### New Capabilities
（無全新 capability；為 Flex 素材編輯的進階模式）

### Modified Capabilities
- `material-system`: Flex 素材新增「進階視覺結構編輯」模式（結構樹 + 拖拉 + 屬性面板 + JSON 雙向），為填空模式的進階選配，非預設。

## Impact

- **前端（大）**：
  - 新增進階編輯元件（結構樹 / 屬性面板 / 與現成 renderer 預覽連動）。
  - 引入拖拉套件（repo 目前無 dnd；@dnd-kit 或 vuedraggable 對應框架）——主要工程量。
  - 元件 registry：以宣告式定義每種元件的可編屬性 + allows 巢狀白名單（借鑑 aitago 五檔但簡化成一份 registry）。
  - 視覺 ↔ JSON 雙向切換；undo/redo。
  - 從填空編輯器加「轉為進階編輯」入口。
- **後端**：無新端點（存素材、驗證走既有）。
- **相容性**：body 仍是 LINE Flex JSON；填空 ↔ 進階可互轉（同一份 JSON）。進階改過的複雜結構回填空模式時，填空只顯示能對應的欄位、其餘保留不動。
- **RLS**：無新表。
- **決策點**：本階段標記為「需求驗證後再實作」——若填空 + AI 已滿足使用者，可暫緩或不做。
